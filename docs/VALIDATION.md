# Проверка готового MVP

Проверено локально 23 сентября 2026 года на предоставленных файлах организаторов. Среда: Windows, Python 3.12, pandas 3.0.1, NumPy 2.3.5, PyArrow 21.0.0, NetworkX 3.5. Результаты этой проверки не являются оценкой точности реальных ролей.

## Сквозной запуск

```text
python run.py --data data --out results
python scripts/check_submission.py --data data --out results
```

- 2 248 узлов, 3 119 рёбер, 4 840 транзакций.
- 81 seed; сохранены все 19 изолированных seed.
- 35 слабосвязных компонент, из них 16 содержат рёбра.
- 86 структурных кластеров при текущей методике и resolution=1; число не фиксировалось заранее.
- 50 строк в `top_nodes.csv`; у всех узлов обязательные поля заполнены.
- 444 граничных узла; **0** из них получили `terminal`.
- Суммы и n_tx в рёбрах согласованы с исходными транзакциями.
- Повторный полный прогон: **2.82 секунды внутри CLI**, **3.88 секунды с запуском процесса и импортами**. Первое измерение расчёта — 2.33 секунды. На другой машине время может отличаться.
- SHA-256 всех трёх CSV совпал между двумя независимыми полными прогонами.
- `check_submission.py`: PASS.

Большое число `terminal` означает, что множество внутренних узлов имеет малый наблюдаемый выход в данном месяце. Это **не** утверждение о реальном удержании средств. Такие гипотезы требуют полных операций, остатков и следующего периода. `peripheral` означает отсутствие достаточных признаков, а не доказанную периферийность.

У границы: 441 узел с недостаточными признаками и 3 гипотезы консолидации по наблюдаемому входу. Ни одного автоматически назначенного стока.

## Автотесты

`python -m unittest discover -s tests -v` — **15 tests, OK**.

Проверены:

- запрет стока на обрыве;
- сохранение положительных признаков консолидации на границе;
- исключение seed из балансовых правил;
- цензурирование последних двух дней;
- многопризнаковый допуск координатора;
- отсутствие временного порядка внутри дня;
- запрет двойного расходования входящей суммы;
- невозможность использовать будущий вход для прошлого выхода;
- истечение двухдневного окна;
- ошибки сумм и количества операций;
- неизвестные и float-идентификаторы;
- сохранение одинаковых транзакций;
- сквозная воспроизводимость, изоляты и строковые gid в JSON;
- независимость от порядка строк;
- отклонение неверного config.

Дополнительно успешно выполнен отдельный CLI-прогон и проверка сдачи на вымышленном датасете: 30 узлов, 27 рёбер, 27 операций. Он не содержит реальных данных хакатона и используется в GitHub Actions.

## Интерфейс

Проверен во встроенном Chromium-браузере:

- начальная загрузка сводки и карточки;
- раскладка на узком экране и рабочий экран 1440×1000;
- поиск точного 18-значного gid, включая изолированный seed;
- граничный узел с предупреждением и запросом дополнительных данных;
- неизвестный gid показывает понятную ошибку;
- фильтр транзитных узлов показывает 66 результатов;
- вся сеть показывает 2 248 узлов / 3 119 связей;
- переключение кластера и цветовой легенды;
- текстовая гипотеза выбранного кластера;
- в консоли при этих действиях не зарегистрированы JS-ошибки.

Автоматическое подтверждение события загрузки CSV во встроенном браузере не получено (тайм-аут ожидания). Сам `top_nodes.csv` создан и проверен на диске; кнопка использует стандартный Blob-download. Для защиты доступен гарантированный резерв — файл из `results/`. Проверьте кнопку в обычном браузере на машине команды.
