# Демо за пять минут

Перед защитой: открыть терминал в корне проекта, подготовить архив оригинальных данных, установить зависимости, проверить порт 8765 и размер окна браузера. Не рассчитывать на интернет в зале.

## 0:00–0:40 — задача

«Аналитику известны 81 исходный клиент и их исходящие цепочки. Нужно выбрать, кого из 2 248 клиентов проверять первым, и объяснить почему. Выгрузка неполная: четвёртое колено обрезано, межбанк и остатки неизвестны».

## 0:40–1:10 — живой расчёт

```bash
python run.py --data data --out results --serve --open
```

Показать время в терминале, три CSV в папке и сводку интерфейса. Цифры берутся из данных, а не вставлены в интерфейс вручную.

## 1:10–2:10 — приоритетный узел

Выбрать лидера списка. Показать входящих плательщиков слева, исходящих получателей справа, стрелки, альтернативные признаки, слагаемые приоритета. Объяснить: «кандидат-мост» означает структурное посредничество, а не установленного организатора. Высокий исходящий оборот не доказывает источник этих денег.

## 2:10–3:00 — защита от ложного стока

Найти один `truncated_by_depth=True` в `nodes_roles.csv`, скопировать точный gid как текст в поиск. Показать колено 4, предупреждение обрыва и запрос дальнейших исходящих. Даже при нулевом выходе узел не назван `terminal`. Если есть несколько плательщиков, гипотеза консолидации остаётся возможной.

## 3:00–3:40 — транзит или изолированный seed

Выбрать транзитного клиента и показать отношение выхода/входа и временной признак 1–2 дня. Уточнить, что FIFO — совместимость сумм/дат, не доказательство идентичности денег. Либо найти изолированный seed: он не потерян, у него есть отдельный кластер и явно обозначенный недостаток данных.

## 3:40–4:20 — кластеры и произвольный gid

Показать вкладку кластеров и цветовое переключение. Предложить жюри назвать gid, найти его и объяснить роль по числам. Для длинных ID не использовать Excel с числовым импортом.

## 4:20–5:00 — воспроизводимость и границы

Показать README, диаграмму, `check_submission.py`, успешные тесты. Назвать ограничение: меток истинных ролей нет, поэтому accuracy не заявляем; при миллионе узлов меняем хранение графа, приближаем центральность и выдаём подграфы через сервер.

Резерв: автономный `results/dashboard.html` работает без сервера. Если занят порт, использовать `--port 8766`. Если не запускается браузер, открыть локальный адрес вручную.

## Короткие ответы на вероятные вопросы

- **Почему не нейросеть?** Нет размеченных ролей; критерии должны объясняться за минуту. В MVP используются графовые алгоритмы, кластеризация без учителя и правила. LLM можно добавить поверх проверенных фактов после обязательной части.
- **Почему не ровно 8 кластеров?** ТЗ говорит о восьми сообществах с несколькими seed при одной базовой настройке, а не о требуемом общем числе. Наш вес и разбиение по компонентам документированы.
- **Почему 35 компонент, а в тексте 16?** 16 содержат рёбра, ещё 19 — изолированные seed, которые нужно сохранить.
- **Почему 377 превышений выхода над входом?** 354 при положительном входе плюс 23 с нулевым наблюдаемым входом. Это особенности неполной выборки.
- **Что означает score 1?** Насыщение эвристических факторов, не вероятность. При одинаковом приоритете порядок технический — по gid.
- **Вы нашли организаторов?** Мы нашли кандидатов для проверки со структурными основаниями. Утверждать реальную управленческую роль по этим данным нельзя.
